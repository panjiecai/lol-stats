# 微信推送服务 · 换机校对清单

这份文档给「在另一台电脑上重新部署」用。按顺序做完，微信推送就能跑。

---

## 一、先把话说明白：这套东西的边界

**它不是一个装完就能用的软件。** 三件事决定了它只能在特定机器上工作：

| 依赖 | 为什么绕不开 |
|---|---|
| **微信版本必须是适配表里的 7 个之一** | 原生桥按内存地址硬编码调用微信内部函数。版本不对 → 地址错位 → 注入失败甚至崩微信 |
| **必须在本机编译原生桥 DLL** | `dsh-wechat.dll` 和微信版本一一对应，**不能从这台机器拷到另一台复用** |
| **必须知道自己的 wxid** | 要读对应的本地数据库，选错账号直接报错 |

目前支持的微信版本：

```
4.1.15.13  4.1.15.56  4.2.0.11  4.2.0.12  4.2.0.13  4.2.0.52  4.2.0.53
```

**换机第一件事就是确认微信版本。** 不在列表里，后面全白做。

---

## 二、风险说明（请务必读完再决定用不用）

这套方案**不是微信官方接口**，实现方式是：

- **读**：解密读取微信本地 SQLite 消息库（需要从微信进程内存里提取数据库密钥）
- **写**：向微信进程注入 DLL，远程调用其内部发送函数

即使做到了「不开窗口、不碰剪贴板、不模拟按键」，仍然：

1. **可能被判定为异常使用**，导致账号功能受限或封禁
2. **微信更新版本就会失效**，需要等适配表更新后重新编译
3. **无任何官方保障**

建议：只用来发自己的小号/自用号，**不要用在主号上**，观察一段时间再常态化。

## 三、换机部署步骤

### 步骤 0：确认前置环境

```bash
# 微信版本（必须在上面的列表里）
powershell -Command "(Get-Process Weixin | Select-Object -First 1).Modules | Where-Object {$_.ModuleName -eq 'Weixin.dll'} | Select-Object FileName"

# Python 3.10+
python --version

# VS C++ 生成工具（编译原生桥必需）
"C:\Program Files (x86)\Microsoft Visual Studio\Installer\vswhere.exe" -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
```

三项缺一不可。

### 步骤 1：找到微信数据目录

```bash
# 在微信 设置 → 文件管理 里能看到路径，通常是：
#   D:\Documents\weixin\xwechat_files\<wxid>_<随机后缀>\
```

打开该目录下的 `db_storage`，确认有 `session/`、`message/`、`contact/` 三个子目录。

**目录名格式**：`wxid_xxxxxxxxxxxxxxxx_a1b2c3`
- `account` = 整个目录名（含后缀）
- `selfId` = `wxid_` 开头到后缀前（如 `wxid_xxxxxxxxxxxxxxxx`）

### 步骤 2：复制并配置

把 `wx-sender` 整个目录拷到新机器，然后：

```bash
cd wx-sender

# 建虚拟环境
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

编辑 `config.json`：

```json
{
  "account": "这里填目录名，如 wxid_xxx_a647",
  "selfId": "这里填 wxid_xxx",
  "dbDir": "D:/Documents/weixin/xwechat_files",
  "moduleFile": "（这个文件只给 DSH 宿主用，本方案用不到，留空即可）",
  "pageSize": 50,
  "pollSeconds": 2,
  "mediaRoots": ["（截图输出目录，绝对路径）"],
  "chats": []
}
```

### 步骤 3：编译原生桥（关键，不能跳过）

```bash
powershell -ExecutionPolicy Bypass -File .\wechat.ps1 -Action Build
```

**必须编译到 `wx-sender/engine/` 下**，否则程序找不到。如果它默认跑到别处去，用：

```bash
powershell -ExecutionPolicy Bypass -File .\engine\build.ps1 -OutDir "<wx-sender 绝对路径>\engine"
```

产物应该是：

```
engine/
├── current.json              ← 指向本次编译的 DLL
├── profiles.json             ← 微信版本适配表（7 个版本）
└── <hash>/dsh-wechat.dll     ← 编译出的原生桥
```

### 步骤 4：验证只读（不发送）

```bash
# 1. 服务健康检查
.venv\Scripts\python.exe wx_server.py --port 8756
# 另开一个窗口：
curl http://127.0.0.1:8756/health
```

应该返回：

```json
{"ok": true, "chats": []}
```

`chats` 为空是正常的（白名单还没配）。

```bash
# 2. 列出本机所有可发聊天（会读会话库，约 10 秒）
curl http://127.0.0.1:8756/available
```

能列出群和联系人名字 → 说明数据库读取和账号绑定都正常。

**这一步失败，后面别试了。**

### 步骤 5：配白名单并发测试图

**不要一上来就发群。** 先发文件传输助手：

```bash
curl -X POST http://127.0.0.1:8756/config/chats ^
  -H "Content-Type: application/json" ^
  -d "{\"chats\":[{\"id\":\"filehelper\",\"name\":\"文件传输助手\"}]}"
```

然后在 lol-stats 监控面板点「发送测试图」。

文件传输助手收到图 = **全链路通了**。

### 步骤 6：接 lol-stats

启动 lol-stats（0.7.3+），进「监控面板」：

1. 微信推送区 → 填服务地址 `http://127.0.0.1:8756`
2. 点「连接服务」
3. 左侧会列出本机所有聊天，把要发的加进右侧白名单
4. 点「保存」
5. 勾选要发送的目标（这一步才决定真的发）

## 四、常见故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `微信进程已停止 (pid=xxx)` | 读不到进程持有的文件（权限或版本不对） | 微信需登录；确认版本在适配表 |
| `微信核心 DLL 不能唯一核对` | 微信多开或残留进程 | 只留一个微信进程 |
| `不支持的微信构建` | 版本不在适配表 | 升级/降级微信，或等适配更新 |
| `原生桥源码已变化，请先重新 Build` | DLL 与源码不同步 | 重跑 `wechat.ps1 -Action Build` |
| `CHANNEL_TARGET_DENIED` / 不在 chats 里 | 目标不在白名单 | 在配置页加入并保存 |
| 发送返回 ok 但对方没收到 | 原生调用成功但投递未知 | 见下方「已知缺陷」 |
| `群聊需要显式配置 trigger: mention` | 群聊条目缺字段 | 配置页保存会自动补；手改要加 |
| 服务启动报端口占用 | 上次没关干净 | `taskkill /F /IM wx-push-server.exe` |

## 五、必须知道的四个缺陷

### 1. 没有投递回执

微信 4.x 持续写入时，消息库拿不到稳定快照（`SnapshotBusy`），所以：

- **发送只确认「原生函数调用成功」**
- **不确认「对方真的收到」**
- 失败会在日志里报错，成功就是尽力而为

**第一次用务必人工看一眼群。**

### 2. 服务必须常驻

关掉服务 = 推送停。目前没有开机自启，需要手动启动：

```bash
.venv\Scripts\python.exe wx_server.py
# 或打包版
wx-push-server.exe
```

### 3. 微信退出登录后要重启服务

微信重新登录后，进程 PID 变了，服务持有的句柄失效。

### 4. 打包成 exe 后的限制

`dist/wx-push-server.exe` 包含 Python 运行时，**但不包含原生桥 DLL 的跨机可移植性**。

拷贝 dist 到新机器后仍然要：

1. 确认微信版本
2. 在本机重跑 `wechat.ps1 -Action Build`

否则 exe 能启动、能列聊天，但**发送会失败**。

## 六、目录说明

```
wx-sender/
├── wx_server.py          HTTP 服务（/health /available /config /push）
├── wx_send_core.py       发送核心（服务与 CLI 共用）
├── send_native.py        单次发送 CLI
├── config.json           账号 + 白名单 + 媒体目录
├── engine/               原生桥源码 + 编译产物 + 版本适配表
├── adapter.py 等 14 个   原生桥依赖模块（已适配微信 4.x）
├── build-exe.py          打包成 exe
└── dist/                 打包产物（117MB）
```

服务只监听 `127.0.0.1`，不对外暴露。

## 七、校对完成的标准

在新机器上，以下全部成立才算部署成功：

- [ ] `curl /health` 返回 `{"ok":true}`
- [ ] `curl /available` 能列出正确的群和联系人
- [ ] 文件传输助手收到测试图（**亲眼确认**）
- [ ] lol-stats 监控面板「连接服务」显示服务在线
- [ ] 白名单保存后，`config.json` 内容正确
- [ ] 触发一次真实对局导出，图成功进群

前五项是必过的；第六项需要打一局才能验证。
