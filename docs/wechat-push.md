# 微信推送服务 · 现状与缺陷

给后续维护者（以及换机后的自己）看的交接文档。

---

## 一、它是什么

lol-stats 监控账号打完一局 → 渲染战绩卡片 → 通过本机服务发到微信群。

```
lol-stats（轮询 LCU → 渲染 → 截图）
        ↓  HTTP POST base64 PNG
wx_server.py（127.0.0.1:8756，常驻）
        ↓  进程内调用
原生桥 DLL → 微信进程内部发送函数
        ↓
微信群
```

**和影刀方案的区别**：不占剪贴板、不切前台窗口、不模拟按键，可以边玩游戏边发。

---

## 二、为什么它只能在特定机器上跑

这是理解整套东西的前提，也是换机时最容易踩的坑。

| 硬约束 | 原因 | 后果 |
|---|---|---|
| **微信版本必须命中适配表** | 原生桥按内存地址硬编码调用微信内部函数 | 版本不符 → 地址错位 → 注入失败或崩微信 |
| **DLL 必须本机编译** | 每个微信版本的函数地址不同 | 跨机拷贝 DLL 必然失效 |
| **必须知道自己的 wxid** | 要解密对应的本地数据库 | 选错账号直接报错 |

支持的微信版本（见 `engine/profiles.json`）：

```
4.1.15.13  4.1.15.56  4.2.0.11  4.2.0.12  4.2.0.13  4.2.0.52  4.2.0.53
```

**换机第一件事：确认微信版本。** 不在列表里，后面全部白做。

## 三、风险声明

实现方式：**解密读取微信本地 SQLite 数据库 + 向微信进程注入 DLL 调用内部函数**。

即使做到了：

- ✅ 不打开窗口
- ✅ 不碰剪贴板
- ✅ 不模拟鼠标键盘
- ✅ 不修改微信安装文件

仍然存在：

| 风险 | 说明 |
|---|---|
| **账号受限/封禁** | 微信安全中心明确将「违规获取聊天记录」「自动化脚本操控微信」列为治理对象 |
| **随版本失效** | 微信每次大版本更新都可能让适配表作废 |
| **无官方保障** | 这是逆向实现，不是开放 API |

**建议**：只用自用号或小号，不要用在主号上；先低频试用（每局一张属于低频），观察一段时间。

## 四、四个已知缺陷

### 1. 没有投递回执（最重要）

微信 4.x 在持续写入时，消息库**永远拿不到稳定快照**（`SnapshotBusy`）。因此发送路径刻意不读库：

- **只能确认「原生函数调用成功」**
- **不能确认「对方是否收到」**
- 失败会在服务日志报错，成功就是尽力而为

**这是设计取舍，不是 bug。** 如果要回执，就必须能读库建快照，而当前微信版本做不到。

**影响**：第一次使用、或修改配置后，**务必人工去群里看一眼**。

### 2. 服务必须常驻

关掉服务 = 推送停止。目前**没有开机自启**，每次开机需要手动启动：

```bash
cd wx-sender
.venv\Scripts\python.exe wx_server.py
```

### 3. 微信重新登录后必须重启服务

微信重登后进程 PID 变化，服务持有的进程句柄失效。表现是发送全部失败，日志报「微信进程已停止」。

### 4. exe 跨机仍需重编译

`dist/wx-push-server.exe` 打包了 Python 运行时，但**原生桥 DLL 不在其中**（也没法在）。

拷到新机器后的真实情况：

| 操作 | 结果 |
|---|---|
| 双击 exe | ✅ 能启动 |
| `/health` | ✅ 正常 |
| `/available` | ✅ 能列出聊天 |
| `/push` 发送 | ❌ **失败**（DLL 版本不符） |

必须先在新机器跑 `engine\build.ps1` 重编译。

## 五、双闸门设计

配置页把「白名单」和「勾选」做成两个独立操作，这是有意的：

| 操作 | 作用 | 写哪里 |
|---|---|---|
| **保存白名单** | 服务**允许**发往哪些群 | 服务端 `config.json` |
| **勾选** | 这次**发给谁** | 浏览器 localStorage |

两者都通过才真正发送。即使前端被绕过，服务端仍会拒绝白名单外的群（返回 403）。

**加群必须人工操作**，任何自动化流程都无法自行添加。

## 七、换机部署时的检查顺序

1. `python --version` ≥ 3.10
2. 微信版本在适配表里
3. VS C++ 生成工具存在
4. `pip install -r requirements.txt` 成功
5. `cp config.example.json config.json` 并填对 `account` / `selfId` / `dbDir`
6. `engine\build.ps1 -OutDir <绝对路径>\engine` 编译成功
7. `curl /health` 返回 `{"ok":true}`
8. `curl /available` 能列出聊天
9. 往文件传输助手发一张测试图，**亲眼确认收到**
10. lol-stats 监控面板连接服务、配白名单

前 9 步全部通过，才算部署成功。

详细步骤见 [换机校对清单.md](./换机校对清单.md)。

## 八、排查速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `微信进程已停止 (pid=xxx)` | 读不到进程文件 | 微信需登录；查版本 |
| `微信核心 DLL 不能唯一核对` | 微信多开/残留 | 只留一个微信进程 |
| `不支持的微信构建` | 版本不在适配表 | 换微信版本 |
| `原生桥源码已变化，请先重新 Build` | DLL 与源码不同步 | 重跑 `build.ps1` |
| `xxx 不在 config.json 的 chats 里` | 目标不在白名单 | 配置页加入并保存 |
| `群聊需要显式配置 trigger: mention` | 群条目缺字段 | 配置页保存会自动补 |
| 端口 8756 被占用 | 上次未退出 | `taskkill /F /IM wx-push-server.exe` |
